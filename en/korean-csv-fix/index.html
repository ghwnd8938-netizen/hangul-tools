Why it happens

A CSV file is plain text and does not say which character encoding it uses. Korean text is usually stored in one of two ways:

  • UTF-8, the modern standard used by Google Sheets and most web services.
  • CP949 (often called EUC-KR, or “ANSI” on Korean Windows), the legacy Korean encoding. Older Korean business systems often still export it, and Excel’s “CSV (Comma delimited)” format saves in it on Korean Windows. Some statement exports and public-data downloads are CP949 too.

When you double-click a CSV, Excel for Windows looks for a byte order mark (BOM, the bytes EF BB BF) at the start. With a BOM it reads the file as UTF-8; without one it uses the computer’s legacy code page: Windows-1252 on English systems, CP949 on Korean ones. So a CP949 file is garbled on a non-Korean PC, and a UTF-8 file without a BOM is garbled on most Windows PCs. Google Sheets and most programs expect UTF-8, so CP949 files break there.

The fix is the same either way: read the file with the right encoding and save it as UTF-8, with a BOM for Excel and without one for everything else.

FAQ

Does the content change?
No. Characters, commas, quotes and line endings (CRLF/LF) stay exactly as they were; only the encoding and the BOM change.
Is it safe to use with bank statements?
The page has no server side: the file is processed by JavaScript in your browser and nothing is sent over the network. You can confirm this in your browser’s developer tools (Network tab).
BOM or no BOM?
Use the BOM version for Excel. Google Sheets reads UTF-8 with or without a BOM. Some programs treat the BOM as part of the first column name, so they are better off without it. In Python, encoding="utf-8-sig" strips a BOM, and encoding="cp949" reads the original Korean file directly.
Can it convert to CP949/EUC-KR, e.g. for uploading to a Korean site?
No. The text encoder built into browsers can only write UTF-8. A text editor such as VS Code (“Save with Encoding” → Korean (EUC-KR)) can do it.
I converted it and it is still garbled.
If the file was opened and saved in Excel while it looked garbled, parts of the original text may be lost for good. Download the original again and convert that. Alternatively, Excel’s Data → From Text/CSV lets you pick the file origin “949 : Korean” yourself.

Limitations

  • Auto-detection is a guess: valid UTF-8 is treated as UTF-8, anything else as CP949. Short files with very little Korean can be misjudged. Other legacy encodings (accented Western text in Windows-1252, Japanese Shift_JIS, Chinese GBK) are not supported.
  • UTF-16 files (Excel’s “Unicode Text”) are recognised only if they have a BOM or contain some English letters or digits.
  • Real Excel workbooks (.xlsx, .xls) are not text files and are rejected.
  • The whole file is processed in browser memory, so files of several hundred MB may be slow or fail.
